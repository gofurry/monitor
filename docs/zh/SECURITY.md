# 安全政策

## 支持版本

安全修复会提供给最新发布版本和当前 main 开发分支。

## 报告漏洞

请不要在公开 issue 中报告安全漏洞。

如果本仓库启用了 GitHub 私密漏洞报告，请优先使用该功能。如果不可用，请创建一个最小化的公开 issue，请求私密联系方式，不要包含利用细节、日志、token 或敏感环境信息。

报告时请尽量包含：

- 受影响的版本或提交
- 简洁的问题描述
- 复现步骤或 proof of concept
- 预期影响
- 已知缓解方式

## 响应

这是一个小型开源项目，没有正式的安全响应 SLA。维护者会尽力确认有效报告、调查问题，并在适当时发布修复或缓解方案。

## 范围

`monitor` 是一个轻量 `net/http` 中间件。以下类型的安全报告最有帮助：

- 敏感运行时数据暴露
- 监控端点中的不安全 HTTP 行为
- 可能影响被包装服务的请求处理 bug
- 对本包有实际影响的依赖漏洞

## 仪表盘暴露风险

监控端点会暴露进程、runtime、主机、网络、容器和 HTTP 流量统计。请将它视为运维端点，而不是公开应用页面。

- 生产环境使用 `Config.Authorize` 或上游认证代理。
- 在可行时通过网络层限制访问，并且只通过 TLS 提供端点。
- 不要把 Bearer token 或其他凭据写入源码、URL 或日志。
- 优先使用同源 `FaviconURL`；远程 favicon 会向其他主机暴露仪表盘访问行为。

`Authorize` 只作用于配置的监控路径，并在 HTTP 方法处理之前执行。被拒绝的 HTML、JSON、`HEAD` 和不支持的方法请求都会返回 `401 Unauthorized`。本包不提供 TLS、token 存储、限流或角色管理。

JSON 快照刻意排除可执行文件完整路径、工作目录、环境变量、构建元数据和远程仓库 URL。采集失败只暴露稳定标识，不返回底层操作系统错误文本。
